# 游戏规则（唯一真相源）

> **改代码之前先改这份文档；改完文档再改代码。**
>
> 为什么这份文件这么重要：战棋的 bug 几乎全部来自"规则边界情况没定义清楚"，
> 而不是算法写错。用 AI 迭代时，Agent 每加一个机制都会来读这份文件，
> 没有它就会出现"规则漂移"——同一个概念在 combat.ts 和 ai.ts 里理解不一样。
>
> 本文档描述的是**当前已实现**的规则，与 `src/core/` 里的代码一一对应。
> 凡是文档里没写的，就是还没实现。

---

## 1. 网格与坐标

- 地图是**方格**，坐标 `(x, y)`，`x` 向右、`y` 向下，原点在左上角。
- 距离一律使用**曼哈顿距离**：`|x1-x2| + |y1-y2|`。
- 移动只允许**四方向**（上/下/左/右），不能斜走。
- 攻击范围也用曼哈顿距离衡量：
  - `range: [1, 1]` → 上下左右 4 格
  - `range: [2, 2]` → 距离**恰好**为 2 的 8 格（**含斜角**）
  - `range: [1, 2]` → 上面两圈合并，共 12 格

> 换成六边形只需要改 `src/core/grid.ts` 里的 `DIRS4` 和 `manhattan`，
> 寻路、攻击范围、AI 会自动跟着变。

## 2. 地形

| 地形 | 进入消耗 | 防御 + | 闪避 + | 回合回复 | 说明 |
|---|---|---|---|---|---|
| 平原 plain | 1 | 0 | 0 | 0 | 基准地形 |
| 道路 road | 1 | 0 | 0 | 0 | 视觉区分用 |
| 森林 forest | 2 | 1 | 20 | 0 | 主要掩护 |
| 丘陵 hill | 2 | 2 | 10 | 0 | |
| 山地 mountain | 3 | 4 | 30 | 0 | 难走但极难被打中 |
| 水域 water | **不可通行** | — | — | — | `moveCost: null` |
| 要塞 fort | 2 | 3 | 30 | **2** | 唯一能回血的地形（**被敌人贴住时不回复**） |

规则细节：

1. **地形加成始终取自"承受方所在格"**。站在森林里的单位防御 +1、被命中率 −20。
2. 地形**不影响攻击**。森林不会让箭矢射不出去，只影响被打的难度。
3. `moveCost` 是 `null` 表示**完全不可通行**，不是"花费很大"。
4. 飞行单位 / 无视地形的移动方式**尚未实现**。

**回血数值的约束（别随手调大）**：本作常规伤害是 5~8 点，但**打在要塞上的**
伤害还要再扣掉防 +3，只剩 4~5 点。回血一旦接近它，站在要塞上的单位
每回合净掉血趋近于 0，1v1 就永远打不完。

**⚠️ 更关键的一条规则：被敌人贴住的单位不能回复。**
要塞同时给了 防 +3、闪避 +30、回血，三者叠加会让防守方在数学上不可杀死 ——
实测（枪，被斧克）打站在要塞上的山贼：伤害 5、命中仅 30%，期望每回合 1.5 点，
而对方回血 2 点。**回血比伤害还快**，第三关因此出现 1.3% 永远打不完的对局。
判据直接复用"是否处于敌方控制区"（见 4.1），两者定义完全一致。

这让要塞的定位更清晰：**它是让你脱战重整的地方，不是让你原地耗死别人的地方。**

## 3. 单位与武器

单位模板在 `data/units.json`，武器在 `data/weapons.json`，两者用 `weaponId` 关联。

### 3.1 单位属性

| 字段 | 含义 |
|---|---|
| `maxHp` | 最大生命值 |
| `atk` | **基础**攻击力。实际攻击力 = `atk + weapon.might` |
| `def` | 防御力，直接减免伤害 |
| `spd` | 速度，同时决定**闪避**和**追击** |
| `skill` | 技巧，决定**命中率** |
| `mov` | 移动力，一回合内可消耗的总点数 |
| `weaponId` | 装备的武器 |

### 3.2 武器属性

| 字段 | 含义 |
|---|---|
| `kind` | 类别：`sword` / `axe` / `lance` / `bow` / `tome`。决定相克关系 |
| `might` | 攻击力加成 |
| `hit` | 命中加成（百分点） |
| `crit` | 暴击加成（百分点） |
| `range` | 攻击距离闭区间 `[min, max]` |

**射程是武器的属性，不是职业的。** 弓手只能打 2 格，是因为 `short-bow` 的
`range` 是 `[2, 2]`，而不是代码里特判了"弓手"。换一把武器，射程立刻跟着变。

**反击能力也不需要单独的字段。** 弓手在距离 1 打不到人，所以自然反击不了 ——
旧版本的 `canCounter` 标记因此被删掉了。少一个字段就少一处数据不一致。

**武器内嵌进单位实例**（`unit.weapon` 是一份完整的纯数据，不是 id）。
这样 `state` 依然自洽：战斗公式不需要查全局表，存档也不用连带保存武器定义。

### 3.3 武器相克（武器三角）

```
剑 sword  >  斧 axe  >  枪 lance  >  剑 sword
```

弓和魔法**不入环**：它们既不被克也不克人，靠射程和命中立足。

| 关系 | 攻击力 | 命中 |
|---|---|---|
| 占优 | **+1** | **+10** |
| 不利 | **−1** | **−10** |
| 无相克 | 0 | 0 |

> 火纹用的是 ±15 命中。这里只给 ±10：本作的命中基数比火纹低，
> ±15 会让优势方冲到 90+ 而劣势方掉到 45 以下 —— 那不是"选择"，是碾压。

**为什么相克有效**：它让"打谁"变成一个真实的选择。玩家会为了吃到
+1 伤害 / +10 命中而调整站位。⚠️ 但**前提是双方都有多种武器类型**：
如果敌人清一色是斧头，玩家全员用剑，相克就只是白送 ——
实测那样会让第一关胜率从 75% 直接飙到 99.8%。见 README「武器相克上线后」。

### 3.4 设计约束（改数值时别破坏）

- 弓手 `range: [2, 2]` → 能在 2 格外白嫖近战，但被贴脸时**完全无法还手**。
- 近战 `range: [1, 1]` → 正面对砍会互相受伤。
- 术士 `range: [1, 2]` → 唯一能远距离反击的职业，代价是脆。
- 剑 = 准 + 会心，斧 = 威力大但打不准，枪 = 中庸。三者的"总价值"要大致相等。

### 关卡设计意图：以质换量

三张关卡都刻意做成**不对称**的：

- **玩家** 人少，但单人属性全面占优（血厚、命中高、有远程）
- **敌人** 人多，单人更脆，但攻击力和玩家前排几乎相同

具体到一次交换：士兵打山贼 7 点，山贼打士兵 6 点 ——
**每一下的伤害几乎对称**，差别只在血量、命中率和人数上。

这样设计的好处是"人数"变成了一个干净的旋钮：加一个山贼 ≈ 加一份输出，
不会同时改变单位之间的克制关系。调平衡时只需要动这一个维度。

**头目的设计原则**：本作没有破甲、没有包夹、没有背刺，
所以"高防御的头目"在数学上就是无解的 —— 玩家打不动它，它每回合满额输出。
贼首的定位因此是 **血厚、攻击中等、防御偏低** 的伤害吸收器
（`hp 32 / atk 11 / def 3`），靠血量吃伤害，而不是靠防御弹开攻击。
这样它需要两三个单位围杀几回合，是威胁但不是墙。

当前 `pnpm sim 800` 结果：

| 关卡 | 我方胜 | 平均残存 | 平均回合 |
|---|---|---|---|
| 1. 边境平原 | 75.3% | 1.5 / 4 | 7.8 |
| 2. 迷雾森林 | 74.3% | 1.7 / 4 | 8.9 |
| 3. 峡谷要塞 | 66.9% | 1.1 / 5 | 11.5 |

> ⚠️ 这些数字是**同一套贪心 AI 打自己**跑出来的，衡量的是"纸面实力差"，
> 不代表玩家有两成多的概率输 —— 人比贪心 AI 强得多（会集火、会撤残血、会守隘口）。
> 详细说明见 README「数值平衡是怎么调出来的」。

### 战役与存档不属于战斗规则

这一份只管**战场内**的规则。战场之外还有一层：

- **进度**：第一关永远开放，之后每关要求前一关通关；战绩只保留更好的一次
  （先比残存人数，再比回合数）。实现与单测见 `src/core/campaign.ts`。
- **名册**：我方角色跨关卡保留成长，见下方。
- **存档**：`localStorage` 存进度 + 名册 + 一个"中途对局"槽位，每次动作后自动写。
  实现与单测见 `src/game/storage.ts`。

这一层同样遵守"纯数据 + 纯函数"的约定：`Progress` 可以 JSON 序列化，
所有变更走 `recordClear` / `exportRoster` 这样的纯函数。区别只在于
它的**容错策略是宽容** —— 存档损坏时丢掉坏的那部分继续玩，
而不是像加载地图那样严厉报错。用户此刻什么都做不了，崩掉只会更糟。

### 名册：成长怎么带到下一关

`Progress.roster` 是一个 `Record<槽位名, { level, exp, stats }>`。

**槽位名**形如 `soldier#0`、`archer#0`，规则是「兵种 id + 同兵种第几个」。
**不能用战场实例 id** —— 那里面含出生点下标，换一张地图就变了，等级就带不过去。

**存绝对值而不是"相对模板的加成"**：存档里写的是什么，单位就是什么，
一眼看得懂，读取时也不用回头查单位模板。
代价是以后大改 `data/units.json` 的数值时老存档不会跟着变 ——
那时候把 `storage.ts` 里的 VERSION 加一让旧档作废就行（机制已经有了）。

几条明确的行为约定：

1. **输了也保留这局挣到的经验。** 否则"打不过就退出重来"会变成严格更优的策略。
2. **开场 HP 补满。** 每关从头开始，不然上一关的残血会一路滚下去。
3. **敌人不进名册。** 它们的等级由地图里的 `spawn.level` 指定，每次开打重新算。
4. **名册里没有的角色保持模板数值** —— 新加入的队友（比如第三关的重骑）从头开始。

### 威胁范围显示（按 T）

**这不是规则，是 UI 辅助**，不改任何结算。但它的语义容易被写错，所以记在这里：

> 威胁范围 = 某方所有存活单位**先移动、再攻击**能覆盖到的全部格子。

不是"以当前位置能打到哪"。敌人可以先走再打，所以必须把移动范围展开之后
再算射程。按 `done` 过滤是错的 —— 玩家阶段里敌人的 `done` 全是 true
（那是它们上一轮打完留下的），过滤掉就什么都不剩了。

## 4. 移动

移动范围用 **Dijkstra 在带权图上求最短路径**得到，**不是**"曼哈顿距离 ≤ mov"。

阻挡规则（火纹式）：

| 情况 | 能否进入 | 能否穿过 | 能否停留 |
|---|---|---|---|
| 不可通行地形（水域） | ✗ | ✗ | ✗ |
| **敌方**单位所在格 | ✗ | ✗ | ✗ |
| **敌方**控制区（ZOC） | ✓ | **✗** | ✓ |
| **友方**单位所在格 | ✓ | ✓ | **✗** |
| 阵亡单位所在格 | ✓ | ✓ | ✓（不再占据） |
| 自己的起始格 | — | — | ✓（"原地不动"永远是一个合法选择） |

其他规则：

1. 一个单位一回合**只能移动一次**。移动后仍可以攻击或待机。
2. 移动是**不可撤销**的。（做了移动就落子无悔，取消选择不会退回原位。）
3. 移动消耗按地形累加，超过 `mov` 的格子到不了——**哪怕直线距离看起来更近**。

### 4.1 控制区（ZOC）

**与某一方任意存活单位相邻的格子**，就是那一方的控制区（不含单位自己脚下那格）。
**踏入敌人控制区的瞬间，移动立刻结束** —— 那一格能站，但不能从它继续往外走。

效果是每个单位实际封住的不再只有脚下 1 格，而是周围一圈：
**三个并排的单位能封住一条 5 格宽的通路**，防线才真正成立。
没有 ZOC 的话，任何一条防线都能被一步绕过去。

⚠️ **起点不检查控制区。** 已经在敌人身边的单位必须能脱离，
否则被贴住一次就永远动不了 —— 那是"麻痹"，不是"控制区"。
这条例外也正好让退兵变得自然：往外走一步就离开了控制区，之后畅通无阻。

ZOC 还和地形回复联动，见 2 节：**被贴住的单位不能回血**。

在界面上，移动范围会分成两段：**蓝色**是能自由走动的格子，
**琥珀色**是"踏进去就停"的控制区落点。两者用的是同一次移动范围计算，
所以画出来的和点得动的永远一致。

## 5. 战斗结算

### 5.1 伤害

```
攻击力 = 攻击方 atk + 攻击方 weapon.might
相克修正 = +1 / 0 / −1（见 3.3）
伤害 = max(0, 攻击力 + 相克修正 − (承受方 def + 承受方所在地形的 defBonus))
```

伤害**没有随机浮动**。随机只出现在命中判定和暴击判定上。

### 5.2 命中

```
命中率 = 60 + (攻击方 skill − 承受方 spd) × 5
                + 攻击方 weapon.hit
                + 相克命中修正
                − 承受方所在地形的 avoidBonus
命中率 = clamp(命中率, 5, 100)
```

- 基数取 **60** 而不是 70，因为武器自带平均 +10 命中，两者正好抵消。
  这样引入武器系统时**整体命中率没有漂移**，平衡不用重做。
- 下限 5、上限 100。**没有绝对必中，也没有绝对必失**（除非地形加成把上限顶到 100）。
- 判定用 `<`：`chance = 100` 时必定命中，`chance = 0` 时必定落空。

### 5.3 暴击

```
暴击率 = clamp(攻击方 weapon.crit, 0, 60)
暴击伤害 = 普通伤害 × 3
```

**暴击率只看武器，不掺技巧。** 这是刻意的：

1. 掺技巧就意味着每次交战都要多掷一次骰，命中率的分布全乱。
2. 更重要的是，掷骰次数一变，"同一局面必然得出同一结果"这件事就更难验证 ——
   而这是整个项目可复现性的根基。

**掷骰顺序**（这决定了随机游标怎么推进，任何改动都会破坏旧存档的复现性）：

1. 先掷命中。**落空就到此为止，不掷暴击** —— 没打中谈不上会心。
2. 命中之后再掷暴击，**且只在 `crit > 0` 时才掷**。
   `crit = 0` 的武器不消耗游标，否则每次命中都会多一次必然失败的骰子。

### 5.4 打击顺序

一次交战最多发生 **4 段打击**，按顺序执行：

| 段 | 出手方 | 触发条件 |
|---|---|---|
| 1 | 攻方 | 总是 |
| 2 | 守方反击 | **守方的武器射程够得着攻方** |
| 3 | 攻方追击 | `攻方 spd − 守方 spd ≥ 4` |
| 4 | 守方追击 | 第 2 段成立 **且** `守方 spd − 攻方 spd ≥ 4` |

**中断规则：任意一段造成击杀后，剩余所有段落立即取消。**

- 攻方一击杀死守方 → 守方不会反击，攻方也不会追击。
- 守方反击杀死攻方 → 攻方的追击不会发生。

每段打击**独立掷骰**。所以"命中率 60% 打两下"有可能是"中一下、空一下"。

### 5.5 结算与重放共用同一个函数

`simulateCombat()` 是纯函数，只依赖入参，返回完整的打击事件序列。
**`resolveCombat`（真实结算）和表现层的战斗重放调的是同一个它。**

早先表现层是照着 `resolveCombat` 的循环重写一遍，靠"对账检查"兜底。
加入暴击骰之后那种写法必然出事（掷骰次数变了，游标推进方式就变了），
所以直接抽成共用的纯函数 —— 两边不可能对不上。

### 5.6 战斗预测（UI 显示用）

预测的语义是**"如果双方全部命中、且都不暴击会怎样"**，因此它是确定性的、不消耗随机数。
它按同样的 4 段顺序模拟，并在计算过程中应用中断规则。

暴击**只作为概率显示，不计入伤害预期** —— 否则玩家会以为那是必然结果。

### 5.7 经验与升级

**经验来源**（每次交战结算一次，按打击逐段累加）：

| 情况 | 经验 |
|---|---|
| 命中并造成伤害 | 15 |
| 击杀 | 额外 +35 |
| 落空 | 1 |
| 敌人每高一级 | 每次结算额外 +5，**最多算 5 级差** |

- 等级差**只往上加成**：打比自己弱的敌人不倒扣。
  倒扣的话玩家会不敢收残兵，而那恰恰是战棋里最正常的操作。
- 等级差**必须封顶**（5 级）。不封顶的话它会变成一台失控的发电机：
  一场拖长的战斗里双方互相攻击几十次，每次都按"敌人比我高 19 级"结算，
  于是双方一路顶到满级 —— 而那又反过来让战斗更打不完。实测能打出 50 回合僵局。
- **只给活下来的单位**：阵亡了还给经验没有意义（升级也白升）。
- **守方一次都没反击过就没有经验**。这是"弓手贴脸挨打不还手"的直接后果。

**升级**：攒满 100 点升一级，多出来的经验留到下一级，可以连升。
等级上限 **10**；满级后经验不再累积。

> ⚠️ **上限只有 10 是刻意的。** 本作的武器威力是固定的（铁器档 3~6），
> 而 HP 成长有 60~80%、防御成长 25~50% —— 等级越高，伤害相对越跟不上。
> 实测放到 20 级时，两个高等级单位站在要塞上互相只能造成 0~2 点伤害、
> 命中 20%，直接打出僵局。**上限 10 让整条数值曲线留在能出结果的区间里。**
> 以后加了武器档位（铁 / 钢 / 银）再考虑放宽。

**成长**：每升一级，对 HP / 攻 / 防 / 速 / 技 **各掷一次骰**，
掷中（按 `growths` 里的百分比）就 +1。
掷骰走的是**可播种随机**，所以同一个种子下成长完全相同 —— 模拟器和回放才站得住。

- 成长率为 0 的项**不掷**，不浪费游标（和"暴击率为 0 时不掷暴击骰"同一个原则）。
- 升级涨了生命上限时，**多出来的那一份同时补进当前 HP**。
  否则"涨了 3 点上限但血没动"会让玩家觉得白涨。

**掷骰顺序**（这决定了随机游标怎么推进，改动会破坏旧存档的复现性）：

```
打击（命中 → 暴击）→ 攻方经验结算（连升 n 级就掷 n 轮成长）→ 守方经验结算
```

⚠️ **这段逻辑写在 `simulateCombat` 里，不是另开一个函数。**
因为它消耗随机游标，而游标必须和打击结算走同一条路径 ——
否则表现层的战斗重放对不上账，飘字顺序就全乱了。

### 5.8 等级自带属性

**等级 N 的白板属性 = 模板属性 + 成长率的期望值 × (N − 1)，向下取整。**

这条**不是可选的**。如果等级只影响经验公式而不影响属性，那它就是纯粹的
"给玩家送经验的数字"，而且会变成**正反馈**：敌人等级越高 → 玩家吃到的等级差
经验越多 → 玩家滚雪球。实测第三关的敌人挂着 3~4 级却没有任何属性加成时，
胜率从 63.6% 飙到 87.3%，通关率 85% —— 整个战役直接失去难度。

敌人的等级用**期望值向下取整**（确定性的），因为我方角色的成长走掷骰、
而且有实际结果要保存；敌人不需要"运气成长"，数值确定才好复现。

**我方角色的实际成长值存在名册里，套用时覆盖白板属性。** 见第 12 节。

## 6. 回合结构

```
第 N 回合 = 我方阶段 → 敌方阶段 → 第 N+1 回合
```

- 游戏从 `turn = 1`、`activeTeam = 'player'` 开始。
- 结束一个阶段时，**只重置即将行动一方**的 `done` / `moved` 标记。
- `turn` 只在"敌方阶段结束、切回我方"时 +1。
- 一个阶段内，每个单位最多行动一次（`done` 标记）。
- 玩家可以在还有单位未行动时提前结束回合。
- 切换阶段时同时结算**地形回复**（见第 2 节）：站在恢复地形上、
  **且不与敌人相邻**的单位回血。顺序是"先回复、再开始行动"。

## 7. 胜负条件

每次状态变更后判定：

- 敌方存活单位数 = 0 → `phase = 'won'`
- 我方存活单位数 = 0 → `phase = 'lost'`
- 否则 `phase = 'playing'`

## 8. 随机数

- 全部随机来自 `src/core/rng.ts`，只依赖 `(rngSeed, rngCursor)` 两个整数。
- `rngCursor` **存在 BattleState 里**，每次掷骰 +1。
- 因此：
  - `state` 依然可以整体 JSON 序列化；
  - 相同种子 + 相同操作序列 = 逐字节相同的结果；
  - 存档可以完整回放，headless 模拟可以复现任何一局。

> ⚠️ **不要在 core 层使用 `Math.random()`。** 一旦用了，回放和单元测试立刻全部失效。

## 9. 状态与存档

- `BattleState` 是纯数据：没有 `Map`、`Set`、class 实例、函数引用。
- 存档 = `JSON.stringify(state)`；读档 = `JSON.parse`。
- 所有状态变更必须经过 `applyAction(state, action) -> newState`（`src/core/reducer.ts`）：
  - **纯函数**，绝不修改传入的 state；
  - 非法操作**直接抛错**，不静默忽略；
  - 每次成功后自动判胜负。

## 10. 敌方 AI

贪心 + 权重打分，不做搜索（不写极小化极大、不写博弈树）。

对每个单位：

1. 枚举所有**可停留的落点**（已移动过的单位则只考虑原地）。
2. 对每个"落点 × 射程内敌人"组合，用战斗预测算一个分数：

   | 因素 | 权重 |
   |---|---|
   | 造成伤害 | ×10 |
   | 击杀目标 | +1000 |
   | 被反击伤害 | ×8（负） |
   | 自己阵亡 | −2000 |
   | 目标已损失 HP | ×2 |
   | 距目标距离 | ×1（负，仅作平局打破） |

3. 取最高分。**但若这次交换会让自己阵亡且打不死对方，则放弃攻击**，改为推进。
4. 打不到任何人时，移动到**按地形距离**离最近敌人最近的落点；已经在最近位置就待机。

> ⚠️ 这里的"最近"必须用**地形距离**（`terrainDistanceField`），不能用曼哈顿距离。
> 隔着一条湖的两个单位直线距离只有 2，实际绕过去要 7 步 ——
> 用直线距离的话 AI 会认为"我已经站在最近的落点上了"，于是**永远待机**。
> 实测这样会在第一关制造 0.1% 的永久僵局（`pnpm stall` 抓到的）。

> 由于"放弃攻击"的条件要求**自己会死而对方不会死**，双方不可能同时放弃，
> 所以理论上对局一定会有进展。**但这条论证依赖"血量单调下降"，而它并不总成立** ——
> M5 的地形回复和 ZOC 都破坏过它，各自制造出 1~2% 的永久僵局。
> 现在两处都堵上了（被贴住不回血 + 按地形距离接近），`pnpm stall` 在
> 三关各 2000 局里都是 0 局僵局。**加任何会回血或限制移动的机制之后，
> 都要重跑 `pnpm stall`** —— 这类 bug 只在"偶尔"出现，靠肉眼测不出来。

**相克是自动被利用的**：`scoreAttack` 用的是 `forecast()`，而 `forecast()`
包含相克修正，所以 AI 本来就会优先挑对自己有利的目标打。
不需要为相克写额外的 AI 逻辑 —— 这是"公式集中在一处"的红利。

**尚未实现**：撤退/走位到掩体、集火同一目标、保护濒死友军、威胁范围规避。
